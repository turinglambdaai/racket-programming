# 从零开始用 Racket 写一个 Web Server

> Web 开发听起来是一堆陌生名词，但剥到本质就是一件事：一次请求，一次响应——和函数调用没有区别。这篇用 Racket 把这件事赤裸裸摆给你看。

很多人一听到 “Web 开发”，脑子里立刻冒出一串陌生名词：HTML、CSS、JavaScript、前端框架、后端框架……

如果你 **没有任何前端经验**，这往往是劝退的第一步。

但好消息是：**Web 的本质其实非常简单**，而 Racket 提供了一套极其适合“理解原理”的 Web Server 工具。

这篇文章的目标只有一个：

> **让你真正理解：一个 Web Server 到底在干什么，以及 Racket 是如何优雅地完成这件事的。**

## 一、先别谈“网页”，我们谈“对话”

在最本质的层面，Web 并不神秘，它只是一次 **远程函数调用**。

你可以这样理解：

- 浏览器：
 > “我想要 `/hello` 这个资源”
- 服务器：
 > “好，这是我算出来的结果”

**一次请求 → 一次响应**

这和函数非常像：

```text
(request) -> response
```

Racket 的 Web Server 几乎就是把这件事 **赤裸裸地摆在你面前**。

## 二、你的第一个 Racket Web Server

### 1 准备环境

确保你已经安装了 Racket（8.x 以上）。

我们只用标准库，不需要安装任何第三方包。

### 2 最小可运行示例

新建一个文件：

```racket
#lang racket

(require web-server/servlet
 web-server/servlet-env
 web-server/http
 net/url)

(define (start request)
 (response/xexpr
  '(html
    (body
     (p "Hello, Racket Web Server!")))))

(serve/servlet start
 #:port 8000
 #:servlet-path "/"
 #:launch-browser? #t)
```

运行这个文件。

你会看到浏览器自动打开，页面上显示：

```text
Hello, Racket Web Server!
```

 恭喜，你已经写了一个真正的 Web Server。

## 三、逐行理解：发生了什么？

我们来慢慢拆解，而不是一股脑地记 API。

### 1 `start` 是什么？

```racket
(define (start request)
 (response/xexpr
  '(html
    (body
     (p "Hello, Racket Web Server!")))))
```

这是 **整个 Web Server 的核心**。

Racket Web Server 的设计思想非常 Lisp：

> **Web 程序 = 一个函数**

- 输入：`request`
- 输出：一个可以作为响应的值

你甚至可以暂时忽略 `request`，把它当成一个“环境参数”。

### 2 为什么要返回 response？

`serve/servlet` 要求处理函数返回一个可以作为 HTTP 响应的值。默认情况下，普通字符串或一棵 xexpr 并不会被自动强制转换成 response，所以最稳妥的做法是显式使用响应构造器。

例如：

```racket
(response/xexpr
 '(html
   (body
    (p "Hello"))))
```

`response/xexpr` 会为你创建完整的 HTTP response：默认状态码是 `200`，默认 MIME 类型是 HTML，并把 xexpr 序列化成响应体。

**这对初学者反而更重要：业务函数负责“算出页面”，响应构造器负责把它变成 HTTP。**

### 3 `serve/servlet` 在干什么？

```racket
(serve/servlet start ...)
```

你可以把它理解为：

> “请帮我把这个函数 `start` 变成一个可以被网络调用的程序”

它做了三件事：

1. 启动一个 HTTP 服务器
2. 监听指定端口
3. 把请求交给 `start` 函数处理

## 四、Web Server ≈ 路由函数分发

真实的 Web 应用通常不止一个“入口”。

例如：

- `/` → 首页
- `/hello` → 打招呼
- `/time` → 当前时间

我们来手写一个 **最直觉的路由系统**。

### 1 读取请求路径

```racket
(define (start request)
 (define path
  (filter (λ (segment) (not (string=? segment "")))
          (map path/param-path
               (url-path (request-uri request)))))

 (define (page text #:code [code 200])
  (response/xexpr
   `(html (body (p ,text)))
   #:code code))

 (cond
  [(equal? path '()) (page "Home")]
  [(equal? path '("hello")) (page "Hello!")]
  [(equal? path '("time"))
   (page (format "Time: ~a" (current-seconds)))]
  [else (page "Not Found" #:code 404)]))
```

现在你可以访问：

- `http://localhost:8000/`
- `http://localhost:8000/hello`
- `http://localhost:8000/time`

你会发现一件很重要的事：

> **Web 路径在 Racket 里最终也能整理成普通的数据结构（列表）**

`url-path` 原始返回的是一组 `path/param` 结构；上面的 `map path/param-path` 把每个路径段取成字符串，再过滤根路径产生的空段。

没有魔法，没有 DSL。

## 五、参数 = 函数参数

我们试试 URL 参数：

```text
http://localhost:8000/hello?name=Racket
```

### 1 读取参数

```racket
(define (start request)
 (define query (url-query (request-uri request)))
 (define name-entry (assq 'name query))
 (define name
  (if name-entry
      (or (cdr name-entry) "")
      "world"))

 (response/xexpr
  `(html
    (body
     (p ,(format "Hello, ~a!" name))))))
```

你刚刚完成了：

- 查询参数解析
- 默认值处理
- 把计算结果放进 HTTP response

而且全是 **普通的 Racket 表达式**。

## 六、HTML 不是字符串拼接（但你可以先这么做）

很多教程一上来就引入模板系统，这对新手非常不友好。

先用字符串，完全没问题：

```racket
(define (start request)
 (response/output
  #:mime-type #"text/html; charset=utf-8"
  (λ (out)
   (display
    "<html>
 <body>
 <h1>Hello Racket</h1>
 <p>This page is generated by Racket.</p>
 </body>
 </html>"
    out))))
```

这已经是一个完整网页了。区别是：HTML 字符串写进了 `response/output` 的响应体，而不是把字符串本身误当成 servlet 的返回协议。

等你理解了 Web 的“函数本质”，再学习 HTML 生成 DSL，会非常自然。

## 七、Racket Web Server 的“哲学优势”

如果你来自 C / 嵌入式/函数式背景，你会发现：

### 1 没有框架强迫你学习“套路”

- 没有 Controller
- 没有 Model
- 没有神秘注解

只有：

> **函数 + 数据**

### 2 Web 程序就是普通程序

你可以：

- 递归
- 高阶函数
- 闭包
- 状态机
- continuation（这是 Racket 的大杀器）

Racket Web Server **不是一个“Web 特化语言”**，
它只是把网络请求接到了你的程序上。

## 八、下一步你可以学什么？

在你已经理解本文内容的前提下，后续路线会非常清晰：

1. **response/xexpr**：用 S-expression 写 HTML
2. **会话（session）**：状态是如何保存的
3. **continuation-based web**：Racket 的独门绝技
4. **把 Web Server 当成后端 API**
5. **用 Racket 驱动个人工具、内网服务、自动化系统**

## 结语

如果你之前觉得 Web 开发“很乱、很杂、很重”，
那只是因为你一开始就被带进了“工具森林”。

Racket 提供的是另一条路：

> **先理解 Web 是什么，再决定你要不要复杂化它。**

而一旦你理解了这一点，
Web 就只是你程序世界里的 **另一个输入输出接口** 而已。
