# 把 Racket 嵌进原生应用——嵌入式运行时的通用模式

> 你已经读完了一整本书的 Racket。这一篇回答一个收官问题：Racket 能不能不住在自己的 REPL 里，而是住进别人家的应用——一个 Swift 写的 macOS 应用、一个 C++ 写的 Windows 程序？答案是能，而且这条路已经走通了不止一次。我们把这类「嵌入式运行时」方案的通用模式一次讲透。

## 为什么要“嵌”

假设你要写一个真正的桌面应用：界面要原生、要快、要符合平台的操作习惯；而业务逻辑——数据加工、领域规则、自动化流程——你想用 Racket 写。工程上有三条路。

**第一条：外部进程。** Racket 程序独立运行，UI 程序通过管道或 socket 跟它说话。实现最简单，但代价是两个进程的生命周期要手动对齐：谁先启动、崩溃了谁拉起、升级时怎么搭配版本，全变成你要操心的事。

**第二条：HTTP 服务。** Racket 起一个 Web 服务器（卷七第 53 章你亲手写过），UI 当客户端。这条路上手也不难，但每一次数值交互都隔着网络栈的编解码，本机回环也不例外；而且让用户机器上常驻一个监听端口的服务，分发和维护都变重了。

**第三条：进程内嵌入。** 把 Racket 运行时直接加载进应用的进程，让它和 UI 共享同一个内存空间、同一个生命周期。没有部署拓扑，没有网络往返，启动即可用——代价是你要真正理解「运行时」是什么。

Noise 项目（Bogdan Popa 的作品）和本书作者维护的 Rivet，走的都是第三条路。接下来拆解它们的通用模式。这些模式是跨语言通用的：宿主换成 Swift、C++ 还是别的，故事结构不变。

## 运行时怎么住进一个进程

先回答最底层的问题：一个 Racket 程序跑起来，到底需要哪些东西？

答案是三件套。**运行时库**（Racket CS 体系下就是 Chez Scheme 的动态库，比如 macOS 上的 `libracketcs`）；**boot 文件**（运行时的“公民身份档案”，包含堆镜像和基础库的字节码，运行时没有它就无法启动）；**头文件**（宿主 C 代码 `#include` 的接口声明，声明了初始化函数和执行入口）。

嵌入的基本动作因此是固定的：宿主启动时加载动态库 → 用平台路径找到 boot 文件 → 调初始化函数把运行时拉起来 → 之后就可以在进程内求值 Racket 代码。Noise 的源码把这条链路拆得很细：哪些头文件给谁用、boot 文件由谁在何时加载、iOS 模拟器和真机的差异——本质上都是这一个动作在不同平台上的变奏。

两个容易踩的坑，提前说。**一是版本必须精确匹配。** boot 文件和动态库是同一个编译产物的两半，混用版本会在启动时以神秘的方式崩溃。Rivet 的对策是把「用哪个 Racket CS」变成构建期的显式契约：运行时整体打包进应用，绝不静默回退到机器上恰好装着的另一个版本。**二是线程。** Racket 运行时内部有自己的线程调度，嵌入后它和宿主的事件循环（macOS 的 main run loop、Windows 的消息循环）并存——谁先初始化、回调从哪个线程进来，是每个平台都要认真对待的问题。通用做法是：运行时在主线程初始化，宿主与 Racket 之间的调用收敛到明确的边界上排队，不让任意线程随手穿越语言边界。

## 跨过边界：数据编组

运行时住进来了，接下来要让两边的值互相来往。这一层比想象中琐碎，因为两种语言对「数据」的世界观不同。

Racket 这边，一切皆值：列表、符号、精确有理数、结构体。宿主那边，Swift 有 `Int64` 和 `String`，C++ 有 `int64_t` 和 `std::string`——没有列表，没有符号，整数还有宽度。所以每一次跨界，值都要被**编组**（marshal）：Racket 的整数变成宿主的定宽整数，字符串统一约定 UTF-8 编码，复合数据要么拆成平铺的字段，要么序列化成字节流再在另一侧重建。

编组层是整个方案的粘合剂，它的职责值得单独背下来：**类型翻译、内存归属、错误传播**。内存归属尤其关键——跨界创建的对象由谁释放？通用答案是明确约定：要么值传递（复制过界，各自管各自的），要么引用传递时配对显式的生命周期管理。省略这个约定，等来的就是野指针或内存泄漏，而且是「有时才崩」的那种。

手工写编组代码是可行但枯燥的：每个 RPC 函数的两端各写一遍参数拆装。所以现代方案都选择了同一个思路——不手写，生成它。

## 契约先行：声明一次，两端生成

这是全部模式里最值得你带走的一个，因为它把卷六学的宏系统变成了工程生产力。

思路是：**先用一套声明式 DSL 把「两端共享的接口」写下来，再由工具从这份声明生成两端的粘合代码。** 接口声明就是契约：有哪些过程、参数什么类型、返回什么类型、有哪些事件和共享状态。

Noise 的做法是在 Racket 里定义 `define-record`、`define-enum`、`define-rpc` 这样的宏，用它们写出协议定义，再由宏展开生成对应的序列化代码和 Swift 侧的粘合层。你在卷六亲手写过宏、写过 `#lang`，这里正好看到宏系统的工业级应用：**协议即代码，粘合层即宏展开的产物。**

Rivet 把同一思路推到了三平台。后端用 Racket 声明接口：

```racket
#lang racket/base

(require rivet/backend)

(define-event progress)                ; 事件：后端 → 宿主的单向通知
(define-state counter : Int64 0)       ; 共享状态：两端都能读写的值

(define-rpc (greet [name : String] : String)
  (format "Hello, ~a!" name))

(define-rpc (increment [value : Int64] : Int64)
  (add1 value))
```

构建期，Rivet 从这些声明生成带完整类型的 Swift 和 C++ 客户端 API——宿主侧调用 `greet` 就是一个普通的类型安全函数调用，编组、传输、错误传播全部由生成的代码接管。RPC、事件、共享状态、取消和生命周期走同一个协议（RVT1），也就是说：调用后端、订阅进度、同步一个两边都要读写的数值，用的是同一套机制，不用为每种交互发明一种新管道。

声明式契约还有一个不那么显眼的好处：**它让两端可以独立进化。** 后端重构内部实现，只要契约不动，宿主代码一行不改；反过来，UI 换掉整个框架，Racket 后端也浑然不觉。契约是跨语言架构里唯一需要稳定的东西。

## 多平台分发：让用户真的装得到

模式讲完，剩下的是工程现实：你的应用要跑在用户的机器上，而用户的机器是 x86_64 或 ARM64，是 macOS、Windows 或 Linux。

嵌入式方案的分发矩阵因此是「平台 × 架构 × 运行时」的三维乘法：每个目标都要有对应的运行时库和 boot 文件，宿主二进制也要按目标编译。Noise 时代的做法是手工构建 XCFramework 把 Apple 平台的产物打在一起，配合 ctool 处理 Racket 代码到 C 工具链的依赖——能走通，但每加一个目标平台都是一次手工劳动。

这套劳动本身是可以被自动化的：把「编译 Racket 运行时 → 编译后端 → 生成宿主粘合层 → 出应用包」写成 CI 流水线，每个目标平台一组产物，发布时一次性出齐。Rivet 用持续集成矩阵维护多平台产物，配合 `raco pkg install` 把框架本体变成一条命令可安装——

```bash
raco pkg install --auto rivet
raco rivet new hello   # 生成一个可构建、可运行的脚手架项目
```

对比一下这条路的两个时代：十年前嵌入一个 Lisp 运行时是 C 层的冒险，今天它是一条包管理器命令。**基础设施成熟的意义就在这里：让下一批人从「打通链路」直接跳到「解决问题」。**

## 从模式到产品

最后回答那个最初的疑问：这条路真的能走多远？

它能走到「商业应用」那么远。Taskly——跨平台任务管理器，macOS 上是 SwiftUI 原生界面，Windows 上是 WinUI 3 原生界面，两端的任务、提醒、同步逻辑全部由同一个 Racket 后端驱动；PodLens——播客转译工具，同样是原生 UI 加 Racket 核心。它们不是演示，是发布给真实用户、持续更新的产品。本书作者的日常开发节奏就是证据：Racket 负责的那一半代码，迭代速度不输任何一门「主流后端语言」。

把这一篇的模式收拢成一张清单，供你设计自己的嵌入方案时对照：

1. **进程内嵌入**，换取零部署拓扑和共享生命周期；版本精确匹配，不给运行时「就近回退」的机会。
2. **运行时三件套**（库、boot 文件、头文件）构成嵌入的最小集合；初始化在主线程，语言边界上排队穿越。
3. **编组层管三件事**：类型翻译、内存归属、错误传播；能生成不手写。
4. **契约先行**：接口声明一次，两端代码生成；RPC、事件、共享状态收敛到同一个协议。
5. **分发矩阵自动化**：平台 × 架构 × 运行时交给 CI，不让手工构建成为平台的天花板。

想动手，从 `raco rivet new hello` 开始；想深入，Rivet 与 Noise 的源码都是开放的——前者看三平台的完整工程化，后者看 Apple 平台上每一步的来龙去脉。

## 结语

这本书从「写几行文字，电脑就会动」开始，一路走到了语言工场：你能造类型、造控制流、造语言，现在你也知道，这些语言和程序可以住进任何宿主、交付给任何用户。

Racket 的终极形态从来不是「又一个脚本语言」，而是**应用逻辑的通用底座**：宏系统让你定制语言，契约让你跨越边界，嵌入让你进入原生世界。工具已经在你手里，剩下的问题只有一个——你想造点什么？
